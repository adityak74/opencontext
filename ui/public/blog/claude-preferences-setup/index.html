Claude Preferences vs Memory: What's the Difference

Claude has two separate personalization systems that solve different problems. Instructions for Claude (Settings → Profile) is a fixed system prompt you write once, and it stays identical in every chat until you change it. Memory (Settings → Capabilities → Memory) is a running summary Claude writes on its own from your conversations, so it evolves without you touching it. Use Instructions for things that rarely change — tone, formatting, your technical background — and let Memory handle the things that do, like what you're currently working on.

Key takeaways

  • Instructions for Claude is a static, user-written system prompt under Settings → General → Profile that loads into every new chat automatically.
  • Memory, rolled out to all Claude.ai users — free and paid — starting in March 2026, is Claude's own auto-generated summary of past conversations, managed under Settings → Capabilities → Memory.
  • Instructions suit stable preferences (communication style, formatting, expertise level); Memory suits context that naturally changes (active projects, recent decisions, current focus).
  • open-context's Claude exporter generates two separate files that map directly onto these two systems: claude-preferences.md for Instructions and claude-memory.md for Memory.
  • Neither is the same as the open-context MCP server, which gives Claude Code and Claude Desktop a separate, locally-stored memory driven by explicit tool calls.

Two systems, two different jobs

It's easy to assume "preferences" and "memory" are just two names for the same thing. They're not. Instructions is declarative — you decide exactly what goes in, and it never changes unless you edit it yourself. Memory is inferred — Claude decides what's worth keeping based on what you actually talk about, and it keeps updating as new conversations happen. One is a rulebook you author; the other is a notebook Claude keeps for itself.

Mixing them up is the most common reason people feel like Claude "forgets" things. If you write your current sprint goal into Instructions, it'll sit there unchanged next quarter, looking wrong. If you expect Memory to enforce a formatting rule, it might not — Memory is built to summarize context, not act as a fixed style guide.

Instructions for Claude: the part you write

Instructions for Claude lives under your account initials → Settings → General → Profile, in a field labeled "Instructions for Claude" (an older version of the UI called this field "Profile"). Whatever you put there becomes an account-wide system prompt: Claude keeps it in mind across every new chat, with no need to reference or re-paste it.

This is the right place for anything you'd otherwise repeat at the start of every conversation — your preferred tone, whether you want code examples by default, how much detail you expect, and background like your role or primary tech stack. Specific instructions work better than vague ones: "keep responses concise" is weaker guidance than a concrete constraint Claude can actually apply consistently.

Memory: what Claude remembers on its own

Memory is the newer of the two features. Claude periodically distills your conversations into a running summary — things like your current projects, recurring topics, and context you've mentioned in passing — and stores that summary rather than a raw transcript. You can review, edit, or delete what's stored at any time under Settings → Capabilities → Memory, and Claude tells you in the chat when it's actually drawing on a memory, so it isn't a black box.

Because Memory is generated from what you actually discuss, it's naturally suited to context that shifts over time: the project you're heads-down on this month, a decision you made last week, a detail from a conversation three days ago that's still relevant today.

Setting up both with open-context

If you're migrating from another AI provider, you already have the raw material for both — it's just scattered across old conversations instead of organized. open-context's preferences editor covers six sections (communication style, technical profile, work context, personal context, current focus, and behavior preferences), and its Claude exporter turns that into two separate, ready-to-paste files:

Generated filePaste into
claude-preferences.mdSettings → General → Profile → Instructions for Claude
claude-memory.mdSettings → Capabilities → Memory

The split isn't arbitrary — the preferences file is built entirely from stable fields (tone, detail level, technical profile), while the memory file is built from the fields that describe your current state (active projects, goals, recent conversation topics), which is exactly the kind of context Memory is designed to hold. If you're starting from a ChatGPT export, the full walkthrough is in the ChatGPT-to-Claude migration guide.

Don't confuse this with the open-context MCP server

There's a third, unrelated layer worth naming so it doesn't get conflated with the two above: open-context also ships an MCP server for Claude Code and Claude Desktop. It's explicit rather than automatic — Claude calls save_context and recall_context tools against your own local JSON store at ~/.opencontext/contexts.json, entirely separate from claude.ai's account-level Memory. It's a good fit for developer workflows where you want context to persist across CLI sessions, not a replacement for either Instructions or Memory. More on that in the MCP persistent memory guide.

Privacy: what stays where

Instructions and Memory both live in your Anthropic account, subject to Anthropic's own data handling. open-context's job stops at generating the files — it runs entirely on your machine, and the only network call it can make is to a local Ollama instance if you opt into AI-assisted preference generation. Nothing about your conversation history is uploaded anywhere by open-context itself.

FAQ

What's the actual difference between Claude's Instructions and Memory?

Instructions for Claude is a fixed system prompt you write once in Settings and that stays identical in every chat. Memory is a running summary Claude writes itself from your conversations, so it changes over time without you editing it.

Do I need to fill in both Instructions and Memory?

No, but they work best together. Instructions cover stable preferences like tone and formatting, while Memory fills in with context that naturally changes, like your current project. Either one alone leaves gaps the other would cover.

Can I see or delete what Claude remembers about me?

Yes. Claude's Memory settings under Settings → Capabilities → Memory let you view, edit, or delete what's stored, and Claude tells you in the chat when it's drawing on a memory.

Is Claude's Memory feature available on the free plan?

Yes. Anthropic rolled out Memory to all Claude.ai users, on both free and paid plans, starting in March 2026.

Is the open-context MCP server the same thing as Claude's Memory feature?

No. Claude's native Memory is automatic and built into claude.ai. The open-context MCP server is a separate, local, tool-driven memory for Claude Code and Claude Desktop, where context is saved and recalled explicitly through save_context and recall_context calls against your own JSON store.
